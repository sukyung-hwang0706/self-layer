# 검사 화면

## 실행

`my-app`에서 `npm.cmd run dev`를 실행하고 `http://localhost:3000/survey`에 접속합니다. 루트 `/`와 기존 `/assessment`에서도 같은 검사 화면을 제공합니다. 제출 후 `/result`로 이동합니다.

## 검사 흐름

- 한 번에 한 문항과 5개 응답을 표시합니다. 응답 선택 후 다음 버튼으로 이동합니다. 미응답이면 다음 버튼은 비활성화됩니다.
- 현재 문항 번호와 전체 108문항 중 응답한 수·진행률을 표시합니다.
- 이전 버튼과 브라우저 뒤로가기·앞으로가기는 문항 위치를 바꾸며 기존 응답을 유지합니다.
- 마지막 문항 다음에는 108개 문항의 응답 확인 화면을 표시합니다. 문항 번호를 누르면 해당 응답을 수정할 수 있습니다.
- 제출 시 모든 문항의 1~5 정수 응답 여부를 다시 검사합니다. 결측이 있으면 결과로 이동하지 않습니다.
- 제출된 응답은 `scoreSurvey`로 계산하고 `analyzeResults`로 분석합니다. 결과 화면은 27개 차원 점수, 근접 성향 안내, 응답 품질 경고를 표시합니다. 응답을 변경하면 다음 결과에서 다시 계산합니다.
- 처음부터 버튼은 확인 후 응답을 지웁니다. 취소하면 그대로 유지합니다.

## 저장과 복구

- localStorage 키는 `self-layers:survey:v1`입니다. 문항 ID별 응답, 현재 문항 위치, 화면 단계와 저장 형식 버전을 저장합니다.
- 응답 선택과 이동 시 즉시 저장합니다. 새로고침이나 페이지 재방문 시 마지막 상태를 복구합니다.
- 결과 자체를 저장하지 않고 응답에서 다시 계산합니다. 손상된 JSON은 초기 상태로 복구하며, 알 수 없는 ID나 잘못된 응답은 버립니다. 미완료 응답으로 결과 단계에 접근하지 못하도록 검사합니다.
- 저장이 차단되거나 저장 공간이 부족하면 경고를 표시합니다. 이 경우 현재 페이지의 메모리 응답은 유지하지만 새로고침 후 복구는 보장할 수 없습니다.
- 서버·계정 간 동기화는 없으며 브라우저 데이터 삭제 시 응답도 삭제됩니다.

## 결과 페이지

- `/result`는 저장된 제출 완료 응답을 읽어 다시 채점합니다. 결과가 없거나 108문항이 완성되지 않았다면 `/survey`로 이동합니다.
- 표시 순서는 결과 요약, 핵심 문장, 네 Layer 평균, 주요·보조 중심 성향, 상위 두 점수 차이, 관계 변화 민감도, 친밀감 거리두기, 반복 패턴 상위 3위, 삶의 방향 상위 3위, 응답 품질, 다시 검사하기입니다.
- 핵심 문장은 계산된 순위에서 결정론적으로 구성합니다. AI나 가상 사례 문구를 사용하지 않습니다.
- 공동 1위는 모두 주요 성향으로 보존하고, 공동 1위를 임의로 주요·보조로 나누지 않습니다. 공동 3위도 모두 표시합니다.
- 강도는 반올림 전 점수로 `<40 낮음`, `<60 보통`, `<75 높음`, `75 이상 매우 높음`을 판정합니다. 표시 점수만 소수점 둘째 자리까지 반올림합니다.
- 네 Layer 점수는 차원별 평균이며 최고 차원 점수와 다릅니다. 관계 영역 평균이 있더라도 ANX·AVO는 각각 설명하며 단일 유형으로 변환하지 않습니다.
- 결과 화면의 응답 다시 살펴보기는 답변을 유지한 채 `/survey`의 검토 화면으로 이동합니다. 다시 검사하기는 확인 후 답변을 초기화합니다.
- localStorage 저장이 실패하면 제출 화면에 머물며 오류를 안내합니다. 저장되지 않은 결과를 표시했다고 안내하지 않습니다.
