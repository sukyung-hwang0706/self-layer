## 작업 1: V1.0 설계서 기준 검사·결과 화면 재구현

### 작업 목적

`SELF-LAYERS V1.0 검사 설계서`와 `SELF-LAYERS 결과 리포트 · SAMPLE.html`을 기준으로, 기존 108문항 MVP를 걷어내고 검사 화면·채점·결과 리포트를 처음부터 다시 구현한다. 설계서 파일명은 85문항이지만 본문 합계(18+9+24+15+9+1)는 76문항이며, 본문 기준으로 구현했다.

### 주요 변경 사항

- 삭제: 108문항 데이터(`src/data/questions.json`, `dimensions.json`), 이전 채점·세션·결과 코드와 테스트, `/assessment` 경로, `scripts/survey_data.py`, 이전 문서(`docs/survey-data.md` 등). `package.json`에서 `data:generate`·`data:validate` 스크립트를 제거했다.
- `src/types/assessment.ts`: 6 Layer 코드, 3가지 응답 형식(1·2순위 선택, 5점 평정, 3개 순위), 결과 타입.
- `src/data/items.ts`: 76문항 문항 은행(설계서 원문·역채점 표시 그대로), Part 안내, 노출 순서. Part 3은 같은 코드 문항이 6문항 이상 떨어지는 고정 순서.
- `src/lib/scoring.ts`: 설계서 10장 계산식을 순수 함수로 구현. Core 판정과 동점 규칙(TypeScore → M → 1순위 횟수 → 판정 유보), CoreConfidence·응답 일관성 페널티, Value(문항당 2점 제한), ANX·AVO·스키마 8, STATE와 밴드, Stress Signature, Expansion·Protection, Growth 준비도, 듣고 싶었던 메시지.
- 설계서에 식이 없는 V0.2 규칙(Value Context Diversity, Influence, 강화·반증, 판정 유보 시 기준 Core, 표시 구간)은 임시 규칙으로 구현하고 `docs/scoring-decisions.md`에 원본 규칙이 아님을 밝혀 기록했다.
- `src/data/content.ts`: 9개 Core 해설(건강할 때·스트레스받을 때, 성장 제안, 편지, Self Card), 패턴·트리거·대처·가치·관계·STATE 문구. 사용자 화면 금지어(유형번호, Wing/윙/날개, 통합/분열, 내부 코드)를 쓰지 않는다.
- `src/lib/session.ts`, `src/components/survey/`: 인트로(선택 이름 입력) → Part 안내 → 문항 → 응답 확인 흐름. 1·2순위 선택과 취소, 5점 평정의 포인터 선택 시 자동 이동(키보드 선택은 자동 이동 없음), Part 6 순위, Part별 진행 막대와 남은 시간, localStorage 저장·복구, 해시 기반 뒤로가기, 미응답 제출 차단.
- `src/lib/report.ts`, `src/components/report/`: SAMPLE 구조의 16개 섹션 리포트(표지, 소개, 한 사람으로 읽기, Self Map, Core, Influence·보조 Core, STATE, 두 가지 모드, 메시지, 관계, 패턴, 스트레스, 가치, 교차 해석, 성장, 편지·Self Card). 레이더·게이지·관계 지도·겹침 SVG와 HTML 막대, 상단 목차, 인쇄·응답 수정·새 검사 버튼.

## 작업 2: AI 문장화 추가

### 작업 목적

설계서 10장 흐름의 "AI 문장화" 단계를 추가한다. AI는 규칙엔진이 확정한 결과를 문장으로만 옮기며 점수·판정을 바꾸지 않는다.

### 주요 변경 사항

- `src/lib/narrative.ts`: 모델 입력(확정 결과의 사실 목록, 내부 코드·원응답·점수 숫자·이름 제외), 시스템 프롬프트, JSON 스키마, 출력 검증기. 금지어·숫자·진단 표현·성장환경 추정·비교 표현·근거 없는 Core·다른 호칭·보호 상태의 과제 제안·마크다운·길이를 필드별로 검사해 통과한 문단만 쓴다.
- `src/app/api/narrative/route.ts`: 서버에서 응답을 다시 채점한 뒤 Claude(`claude-opus-5`, 거절 시 자동 재시도 `fallbacks: "default"`, 구조화 출력)를 호출한다. 자격 증명 없음 503, 요청 제한 429, 거절·잘림·형식 오류 502, 잘못된 응답 400.
- `src/components/report/result-screen.tsx`, `report.tsx`, `globals.css`: 결과 화면의 "AI 문장으로 다듬기" 버튼(사용자가 누를 때만 호출), 진행·오류 안내, AI 문단 점선 표시, 기본 문장 전환, 같은 응답이면 결과 재사용. 요약·Core·두 가지 모드·메시지·교차 해석·편지 6개 문단이 대상이다.
- `package.json`, `package-lock.json`: `@anthropic-ai/sdk` 0.128.0 추가.
- `docs/ai-narrative.md`, `AGENTS.md`의 "AI의 역할 제한", README: AI 사용 범위와 설정 방법을 기록했다. `.env.local`(커밋 제외)에 `ANTHROPIC_API_KEY` 자리를 만들었다.

### 검증 결과

- 단위 테스트(`narrative.test.ts`): 모델 입력에 내부 코드·숫자가 없는지, 검증 규칙별 거부, 보호 상태 규칙 — 작업 1의 43개 합계에 포함, 모두 통과.
- E2E: API를 가짜 응답으로 대체해 버튼을 눌러야 호출되는지, 이름이 전송되지 않는지, 적용·전환·재사용, 503 안내를 확인 — 20개 합계에 포함, 모두 통과.
- 키가 빈 `.env.local` 상태의 개발 서버에서 `/api/narrative`가 503(`ai_unavailable`), 빈 응답에 400을 돌려주는 것을 확인했다.
- 실제 Claude 호출은 API 키가 없어 **실행하지 않았다.** AI가 쓴 실제 문장이 검증을 몇 개나 통과하는지는 확인되지 않았다.

### 미완료 사항 및 다음 작업

- API 키 설정 후 실제 호출로 문장 품질과 검증 통과율을 확인하고, 규칙이 과하게 엄격하면 조정한다.
- 설계서 12장의 사람 검토 단계는 없다. 지금은 검증을 통과한 AI 문장이 바로 사용자에게 보인다.
