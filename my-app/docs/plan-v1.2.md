# V1.2 개선계획: 문항 재배치와 복수 Core 해석

작성 2026-10-03. 2026-10-02 작업보고서의 "결정 필요" 항목에 대한 결정과 실행 순서를 기록한다.
이 문서의 수치 기준 중 "검증 후 확정"으로 표시한 것은 모두 앱 임시 규칙이며 설계서 원문 규칙이 아니다.

## 2. 원칙

- 사람을 반드시 하나의 Core로 분류하지 않는다. 순위뿐 아니라 각 Core를 뒷받침하는 근거가 충분한지 본다.
- 2위·3위라는 이유만으로 설명에 포함하지 않는다. 원점수가 같아도 근거가 부족하면 공동 중심이 아니다.
- 성향 구성과 해석의 확실성은 따로 관리한다. 복수 Core라는 이유로 확실성을 낮추지 않는다.
- 반증은 해석 문장을 조정하는 데만 쓰고 점수·순위는 바꾸지 않는다. 다른 Core가 높다는 사실 자체는 반증이 아니다.
- 세 중심 합계로 개별 Core의 점수·순위·대표 Core·CoreConfidence를 바꾸지 않는다.
- 공동 중심·확정 보류 등의 비율은 관찰 지표다. 보기 좋은 비율에 맞춰 기준을 조정하지 않는다. 무작위 응답에서 확정 보류가 많은 것은 실패가 아니다.

## 3. 단계

진행 순서: 0 → 2 → 1(A안 → B안) → 3 → 4 → 5 → 6.

### 0단계 · 기준선과 별도 검증 세트

- V1.1-app 결과를 `validation/archive/round3-v1.1/`에 고정한다.
- 별도 검증 페르소나 15명을 `validation/holdout/`에 만든다(브리프 `validation/holdout-brief.md`). 규칙 조정 중에는 열지 않는다. 6단계 결과를 보고 규칙을 고치면 이 15명도 조정용 자료가 되며, 최종 확인에는 새 사례가 필요하다.
- 검증할 해석 주장:
  - C1 Core 구성 판정(단일 중심·공동 중심·중심 + 함께 작용·중심 확정 보류)이 인물 서술과 일치한다.
  - C2 공동 중심에 포함된 Core마다 독립된 근거가 있다(순위·동점의 부산물이 아니다).
  - C3 "반대 근거 존재"가 실제 해석 불일치를 잡고, 두 성향의 공존은 잡지 않는다.
  - C4 "판단 어려움" 보류는 영향받는 해석에만 걸리고 결과 전체를 보류하지 않는다.
  - C5 세 중심 분포 설명이 개별 Core 판정과 모순되지 않는다.
  - C6 가치·Core 순위가 보기 위치나 정의 순서에 의존하지 않는다.

### 1단계 · 문항 은행 V1.2-app

A안과 B안을 같은 릴리스 안에서 따로 측정해 효과를 분리한다. 상태마다 페르소나 응답을 2회 받는다(V1.0 run1↔run2 Primary 일치 83%).

**A안 · 구조 조정**
- 가치: 각 9회 등장. 보기 위치 A~D에 3·2·2·2회, 3회가 배정되는 위치를 가치마다 분산(각 위치에 두 가치).
- 맥락: 가치별 등장 맥락 수와 맥락당 문항 수 구성을 최대한 비슷하게.
- 세 중심: 18문항 모두 2·1·1 구성, 두 번 나오는 중심은 6문항씩(중심별 최대 6×3 + 12×2 = 42점). 현재는 최대 38·35·39점이고 한 중심이 빠진 문항이 2·5·3개다. Core별 등장 횟수·위치·함께 제시되는 상대 Core도 함께 확인한다.
  - 적용 순서: 기존 문항 안에서 조정 → 어려운 문항은 장면·보기 재작성 → 그래도 의미가 훼손되면 제약 재검토.
  - 배치를 못 맞추면 만점 환산을 자동 대안으로 쓰지 않는다. 환산안의 무작위 평균·분포를 확인하고, 비교가 적절하지 않으면 중심 합계의 화면 노출을 보류한다.
- 가치 동점: 정의 순서로 자르지 않고 함께 표시한다.
- 검토 반영(2026-10-04): 각 Core를 잘 드러내던 기존 보기는 유지한다(E13 DRIVE "능력이 부족해 보일 수 있다", E07 FLOW, E10 DEPTH·AUTH "내 방식과 색깔", E14 재미를 이유로 고를 수 있는 보기). E05·E07·E11·E13·E14·E15는 질문과 네 보기를 함께 다시 쓴다. 새 보기는 문항 장면별 후보 안에서만 고르고, 후보표는 작성 도구로만 쓴다.
- 짝 균형(같은 중심 2회, 다른 중심 3~4회)은 소수의 1회 이탈을 허용 후보로 두고 해당 쌍과 영향을 기록한다.
- 문장 확정 전에 태그를 가린 독해(`validation/tagging/definitions.md`)로 각 보기에서 읽히는 동기·가치를 먼저 적고 의도한 태그와 비교한다.
- 위치 검사: 고정 응답의 결과 반복률이 아니라 위치별 가치 노출, 실제 점수 차이, 동점 처리 순서가 특정 가치를 밀어주는지 본다.
- 몬테카를로 판정: 가치 Top1 각 12.5% ±2%p, Top3 포함률 37.5% ±5%p. 미달 시 1장 ①의 전체 점검.

**B안 · A안 + 이웃 Core 구분 문장**
- TRUST↔ORDER, DEPTH↔INSIGHT 보기가 "같은 행동이라도 무엇을 지키려는가"의 차이를 드러내도록 고친다. 문장마다 Core 정의와 대조한 검토표를 남긴다.

### 2단계 · 원점수 기준 전환

- 강한 보조 Core의 근접 조건을 `TypeScore 차이 ≤ 8`에서 `원점수 차이 ≤ 1`로 바꾼다. V1.1-app에서 두 조건은 같은 응답을 고르므로 결과는 바뀌지 않는다(V1.0 3지선다에서 ≤ 8은 원점수 동점만 해당했다).
- 이 개념은 5단계에서 복수 Core 구성 체계로 흡수한다.

### 3단계 · Core별 지지 근거 기록

9개 Core 모두 산출한다. 새 가중치와 "근거 충분" 기준은 1단계 이후 데이터를 보고 정한다.

| 근거 | 확인 내용 | 주의점 |
|---|---|---|
| Part 1 원점수 | 얼마나 선택되었나 | Core별 등장 기회·배점이 비교 가능해야 함 |
| 1순위 선택 횟수 | 다른 보기보다 우선했나 | 원점수와 겹치므로 따로 가산하지 않음 |
| 선택된 맥락 | 여러 상황에서 반복되나 | 맥락별 등장 기회 차이 고려 |
| Part 2 동기 진술 M | 그 동기를 직접 인정하나 | 선택형 답변과 일치하는지 확인 |
| 연결 신호 | 관련 특징이 함께 나타나나 | 보조 근거 |

### 4단계 · 반증을 해석 문장 단위로 재설계

주요 해석에 포함되는 Core 각각에 적용한다.

| 상태 | 의미 | 처리 |
|---|---|---|
| 지지 근거 충분 | 설명을 뒷받침하고 뚜렷한 반대 근거가 없음 | 설명 유지 |
| 지지 근거 부족 | 설명을 단정할 자료가 부족함 | 해당 설명의 강도 축소 |
| 반대 근거 존재 | 특정 해석과 어긋나는 답변이 여러 맥락에서 반복됨 | 해당 문장 수정·제외, 다른 해석 제시 |
| 판단 어려움 | 응답 패턴이나 자료 부족으로 구분하기 어려움 | 영향받는 해석만 보류 |

- **조건별 해석 충돌 지도**(초안 작성 후 사용자 검토). 단위는 Core 쌍이 아니라 `content.ts`의 구체적 해석 문장이다. 문장마다 (1) 검토하려는 해석 (2) 그 해석과 어긋나는 답변 (3) 두 성향이 공존할 수 있는 상황 (4) 확인 가능한 문항과 등장 기회를 기록한다. "FLOW가 높으면 STAND는 낮아야 한다" 같은 고정 대립 규칙은 쓰지 않는다.
- 반대 선택은 횟수가 아니라 두 보기가 함께 제시된 기회 중 반복된 비율로 본다. 다른 보기를 1순위로 골랐다고 기존 Core를 부정한 것으로 보지 않는다. 원래 Core를 2순위로 고른 것은 공존 가능성을 뒷받침하는 보조 근거로 기록하되, 이것만으로 공존을 확정하지 않는다(두 개를 반드시 고르는 형식에서 2순위는 소극적 선택일 수 있다).
- 같은 장면에서의 선택, 여러 맥락에서의 반복, Part 2 동기를 함께 본다.
- 응답 패턴 플래그는 종류·강도·영향 범위를 구분한다. 문제 신호 문항을 일괄 낮게 답한 경우는 그 신호에 기대는 해석(PATTERN, 강화, 기존 반증)에만 영향을 주고 Part 1 기반 Core 구성에는 주지 않는다. 이것만으로 "잘 보이려는 응답"으로 확정하지 않는다.
- 점수상 공동 중심인데 리포트가 반증으로 한쪽을 사실상 배제하는 경우가 생기면 그 불일치를 검토 목록에 남긴다.

### 5단계 · 복수 Core 구성과 세 중심

**구성**

| 구성 | 판정 방향 | 리포트 해석 |
|---|---|---|
| 단일 중심 | 1위의 근거가 충분하고 다른 Core는 포함 기준 미달 | 중심 Core 설명 |
| 공동 중심(2~3개) | 근거가 충분한 Core가 2개 이상이고 최고점과 근접 | 여러 Core를 동등하게 설명하고 조합 해석 |
| 중심 + 함께 작용 | 1위가 뚜렷하게 앞서고 다른 Core도 근거가 충분 | 중심 Core와 추가 성향의 역할 구분 |
| 중심 확정 보류 | 중심을 정할 근거가 부족하거나 중요한 불일치가 해소되지 않음 | 확인된 경향과 구분하기 어려운 부분 설명 |

- 근접은 원점수 차이로 정의한다. 공동 중심에 포함할 각 Core는 **최고점과의 원점수 차이 ≤ k**여야 한다(연쇄 포함 방지). k는 1단계 이후 동점·1점 차이를 비교해 정한다. 문항 수·배점이 바뀌면 다시 검토한다.
- 해석 대상 집합은 모두 유지하고, 상세 설명만 최대 3개로 제한한다. 3개를 억지로 채우지 않고 중심 Core 하나를 강제로 지정하지 않는다. 경계 동점을 근거 있게 구분할 수 없으면 공동 요약을 쓴다. 경계 동점 Core를 임의로 탈락시키거나 열등한 성향처럼 표현하지 않는다.
- 기존 판정 유보와 강한 보조 Core는 이 체계로 통합한다. Influence는 인접 Core라는 별도 개념으로 유지하되 설명이 겹치면 합친다.
- Protection 등 Core 기준 계산은 공동 중심 Core별로 따로 계산하고, 화면에서는 공통 내용은 합치고 차이만 나눠 보여준다.

**세 중심(보조 해석)**

| 화면 이름 | 내부 매핑 | 합계 |
|---|---|---|
| 본능 중심 | STAND(T8) · FLOW(T9) · ORDER(T1) | S8 + S9 + S1 |
| 감정 중심 | CARE(T2) · DRIVE(T3) · DEPTH(T4) | S2 + S3 + S4 |
| 사고 중심 | INSIGHT(T5) · TRUST(T6) · SPARK(T7) | S5 + S6 + S7 |

- S는 같은 척도와 비교 가능한 측정 기회로 산출한 Core 점수이며 9개 Core 전체로 계산한다.
- 합계가 높으면 "이 중심에 속한 성향들이 전반적으로 높게 나타남"으로 해석한다. 차이의 해석 기준은 검증 후 정한다. 비율이나 확률로 표현하지 않는다.
- 화면 제목은 "반응의 세 중심". 방법론 안내에 에니어그램의 중심 분류를 참고한 검증 중인 보조 해석임을 밝힌다. 생활 만족 채널(SP/SO/SX)과 다른 분류임을 구분한다. 유형번호는 화면에 쓰지 않는다.

**리포트 순서**: Core 구성 요약 → 개별 Core 해석과 근거가 된 답변 → 조합 해석(공통점, 다른 선택으로 이어지는 상황) → 세 중심 분포 → 해석의 한계. 분량은 유지하고 반복 표현을 줄인다. AI 문장화는 판정된 구성과 근거를 따르며 대표 Core를 새로 고르지 않는다(`NARRATIVE_VERSION` 올림).

### 6단계 · 통합 검증

- `SCORING_VERSION`을 올리고 [scoring-decisions.md](scoring-decisions.md)에 새 규칙을 임시 규칙으로 기록한다.
- 단위 테스트: 경계값(k, k+1), 연쇄 포함 방지, 4개 이상 충족, 공존과 반대 근거의 구분, 플래그 영향 범위, 결과 재현성.
- 조정용 30명으로 납득도·골라내기 재판정과 C1~C6 확인 → 기준 고정 → 별도 검증 15명 개봉.
- lint · typecheck · test · E2E.
- 파일럿 150명은 초기 검토 목표다. 기준 확정 시점은 Core별·구성별 사례 수와 필요한 분석에 따라 따로 판단한다.
