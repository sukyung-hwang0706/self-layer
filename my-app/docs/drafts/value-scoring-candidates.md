# 가치 채점 보정 후보 비교 (검토용)

작성 2026-10-04. [plan-v1.2.md](../plan-v1.2.md) 1단계에서 문항 배치만으로 가치 쏠림을 해소하기 어려워, 채점 보정을 정식 후보로 비교했다. 최종 채점식과 화면 점수는 이 비교를 보고 정한다.

## 1. 조건

- 배치: s11 계열 u3(가치 CONTR 8회·REL 10회, 나머지 9회). 문장 미반영, 태그만 넣어 측정.
- 보정 세트: 무작위 응답 20,000(시드 777001)으로 가치별 평균·표준편차·분포를 고정.
- 평가 세트: 별도 무작위 응답 10,000 × 시드 3개. 후보끼리 같은 세트를 쓴다.
- 보정 점수 차이가 보정 표본의 잡음 수준 이하이면 동점으로 본다(A·B: z 0.05, C: 백분위 0.01). 이 처리가 없으면 증거가 같은 두 가치가 보정값의 미세한 차이로 갈려, 정의 순서로 가르는 것과 다를 바가 없었다.
- 도구: `validation/scripts/value-calibration.ts`, 결과 `validation/analysis/value-calibration.md`. 봉인한 15명은 쓰지 않았다.
- 무작위 응답 기준은 실제 사람 분포가 아니다. 보정 점수의 숫자는 "무작위 응답 분포에서의 위치"일 뿐이다.

## 2. 후보

| 후보 | 계산 |
|---|---|
| engine | 현재 엔진. 결합 점수(0.6·Selection + 0.4·Diversity), 동점은 정의 순서 |
| engineTie | 현재 결합 점수, 동점은 나눔(정의 순서 영향 제거) |
| A | Selection만 표준화: (sel − μ) / σ |
| B | 결합 점수 표준화: (score − μ) / σ, 결합 비중 유지 |
| C | 결합 점수의 무작위 분포 내 위치(중간 순위 백분위) |

## 3. 결과

**보정 세트 분포**: Selection 평균은 모든 가치 37.4~37.6으로 같다. 표준편차는 CONTR(8회) 14.7로 가장 크고 REL(10회) 13.1로 가장 작다. 등장 기회가 적을수록 점수가 더 크게 흔들려 극단값(1위)이 잦아진다. 결합 점수 평균은 46.6(AUTH)~49.4(EXP)로 맥락 다양성 때문에 가치마다 다르다.

**한 가치를 꾸준히 고른 응답**(그 가치가 나온 문항의 70%에서 선택): 그 가치가 1위인 비율은 후보 모두 38~49%, 상위 3은 73~82%로 큰 차이가 없다. A는 등장이 적은 CONTR를 덜 드러낸다(1위 38.6%, 상위 3 73.0%, 다른 후보는 41~46%/78~81%).

**두 가치를 비슷하게 고른 응답**: 두 가치가 모두 상위 3인 비율은 90~92%로 비슷하다. 두 가치 점수 차를 전체 퍼짐으로 나눈 값은 engine·B 0.64, A 0.80(과하게 벌림), C 0.34(상단에서 백분위가 포화돼 구분력이 줄어듦).

**엔진과 1위가 달라진 사례**: B·C는 대부분 "엔진이 정의 순서나 다양성 차이로 한쪽을 고르던 경우를 공동 1위로 표시"하는 형태다(예: ACH·REL 모두 Selection 50·Diversity 100). A는 Diversity를 빼서 1위 자체가 바뀌는 경우가 많다(예: CONTR Selection 44·Diversity 100 → GROW Selection 50·Diversity 67).

## 4. 해석

- 정의 순서만 없애도(engineTie) 쏠림은 남는다. 쏠림은 동점 처리가 아니라 점수 자체(등장 횟수에 따른 변동 폭, 맥락 다양성)에서 온다.
- **A**는 1위 균형은 맞추지만 동점이 19%로 많고, 응답 하나에도 순위가 자주 바뀌며(33.6%), 엔진과 36% 다르다. 맥락 다양성 정보를 버리는 대가가 크다.
- **B**는 기존 구성을 유지하면서 1위·상위 3 모두 기준 안에 들고, 사례 검증에서 손실이 없다. 안정성은 엔진보다 조금 낮다(1위 바뀜 21.7 → 26.4%). 대부분 동점이 표시되면서 생기는 변화다.
- **C**는 B와 거의 같지만 상단에서 포화되어, 두 가치가 함께 높은 사람을 구분하지 못한다(0.34). 분포가 크게 비대칭이 아니어서(왜도 −0.06~−0.21) 백분위의 이점도 작다.

## 5. 제안과 남은 결정

- 제안: **B(결합 점수 표준화)** 를 1순위 후보로 한다. C는 분포 비대칭이 커지는 배치에서 다시 비교한다.
- 동점 허용폭(z 0.05)은 동점 발생률을 직접 좌우한다(B 1위 동점 8.5%). 허용폭은 별도 결정이 필요하다.
- 보정값은 문항 배치에 묶인다. 문항이 바뀌면 다시 산출하고, 보정값 버전을 `ITEM_BANK_VERSION`·`SCORING_VERSION`과 함께 기록한다.
- 화면 표시: 순위는 보정 점수로 정하고, 근거로 "9번의 기회 중 6번 선택"과 선택된 맥락을 보여 준다. 보정 점수를 0~100 막대로 그리는 방식은 의미를 정하고 검증한 뒤 도입한다. 순위는 보정 점수로, 막대는 원점수로 그리는 구성은 쓰지 않는다.
- 이 보정은 강제선택형의 구조적 한계(한 가치를 고르면 다른 가치가 덜 선택됨)를 해결하지 않는다. 결과는 개인 안에서의 상대적 우선순위로만 해석한다.
- 문장을 확정한 뒤 조정용 페르소나 30명으로 순위 변화를 다시 확인한다.

## 6. 결정과 추가 비교 (2026-10-04)

결정: **B안을 잠정 채점식으로 채택**하고 구현을 진행한다. 허용폭 z 0.05를 잠정 근접 기준으로 쓴다(검증된 동점 기준이 아님). 화면은 보정 기준의 순위·공동 순위와 실제 선택 근거(기회 대비 선택 횟수, 제시된 상황 범주 대비 선택된 범주)를 보여 주고, 0~100 막대는 보류한다. 선택 횟수로 순위를 재정렬하지 않으며, '자주 선택함'과 '여러 상황에서 선택함'을 독립된 두 증거처럼 강조하지 않는다. 최종 문항 배치에 맞춰 보정값을 다시 산출·검증한 뒤 서비스에 반영한다.

구현(적용 전): `src/lib/value-calibration.ts`
- 배치 지문: 문항 버전·Part 1 맥락·보기별 가치 태그·배점 상한·결합 비중·보정 방식. 보정값의 지문·문항 버전·방식이 현재와 다르면 오류(`ValueCalibrationMismatchError`).
- 공동 1위: 최고 보정 점수와의 차이 ≤ 0.05(연쇄 포함 없음). 상위 3: 3위 점수보다 0.05 넘게 높은 가치 + 3위 점수와 0.05 이내인 가치.
- 테스트: 연쇄 포함 방지, 정확히 0.05 경계, 상위 3 경계 공동, 같은 측정 조건의 같은 점수는 공동, 측정 기회가 다른 두 가치(8번 중 6번·10번 중 6번)는 묶지 않음, 보정값 불일치 오류.
- (갱신) `v1.2-app.2`에서 V1.2-app 문항으로 보정값을 산출해 엔진의 가치 순위에 적용했다. 화면은 순위·공동 순위와 선택 근거를 보여 준다(`docs/scoring-decisions.md` 임시 규칙 11).

허용폭·보정 시드 비교(u3, `validation/scripts/value-tolerance.ts`):

| 허용폭 | 1위 범위 | 상위 3 범위 | 1위 공동 | 엔진 1위가 공동 1위로 | 다른 가치로 교체 | 한 가치 선호: 단독 1위 | 두 가치 선호: 둘 다 1위 |
|---|---|---|---:|---:|---:|---:|---:|
| 0.025 | 12.1~13.4 | 36.2~38.3 | 6.2 | 6.1 | 4.0 | 75.9 | 2.5 |
| 0.05 | 12.0~13.5 | 36.7~38.5 | 8.6 | 8.6 | 3.4 | 75.4 | 3.5 |
| 0.10 | 11.8~13.3 | 36.0~38.8 | 14.2 | 14.2 | 0.7 | 73.8 | 7.3 |

- 엔진과 1위가 달라지는 경우는 대부분 "엔진 단독 1위가 공동 1위가 됨"이고, 다른 가치로 교체되는 경우는 0.05에서 3.4%다. 엔진과의 차이와 응답 1개 변경 시 변화율은 보조 지표로만 본다.
- 보정 시드를 바꾸면 가치별 평균이 표준편차의 0.016 이하로 달라지고, 공동 1위 집합이 달라지는 응답은 1.4%다. 보정값 추정 오차는 0.05보다 작다. 0.05가 사람의 가치 차이를 구분하는 최소 단위라는 뜻은 아니다.
