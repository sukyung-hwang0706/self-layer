## 2. 엔진 버그와 설계 공백

### 2-1. [결함] PATTERN 2·3위 규칙 단정 문장 — `src/components/report/report.tsx:270-272`
- "함께 움직이는 두 번째와 세 번째 규칙"이 점수 구간과 관계없이 `schemaRanking[1..2]`의 설명문(`SCHEMAS[k].text`, 예: "~하는 경향이에요")을 그대로 쓴다.
- 60건 중 3위 점수가 40 미만("낮음")인 경우가 14건, 2위가 40 미만인 경우가 4건, 1위까지 40 미만인 경우가 4건이다. p01 리포트의 "이해받지 못할 기대 · 38 · 낮음 — 내 감정을 충분히 이해해주는 사람을 만나기 어렵다고 느끼는 경향이에요"가 그 예다.
- 페르소나 독자(p01, p07)가 이 대목을 "근거가 앞뒤가 안 맞는다"고 지적했고, 이것이 신뢰 점수를 깎았다.
- **3위와 4위가 동점인 경우가 60건 중 36건(60%)**이다. 스키마는 2문항 평균이라 9가지 값만 나오고, 동점이면 정의 순서(ABN→US)로 정렬된다(`rankBy`). 그래서 어떤 규칙이 리포트에 나오는지가 응답이 아니라 코드의 배열 순서로 결정된다.
- 제안: 2·3위는 중간(40) 이상일 때만 단정형으로 쓰고, 낮으면 "두드러지지 않았어요"류로 낮춰 쓴다. 동점은 "같은 무게로 나온 규칙"으로 함께 표시하거나 노출에서 뺀다. 리포트 규칙 변경이므로 문구·테스트 갱신이 필요하다(채점 로직은 그대로).

### 2-2. [설계 공백] Value 정규화가 EXP를 띄움 — `scoring.ts` 임시 규칙 1
- 무작위 응답에서 Value Top1 분포는 EXP 35.7%(기대 12.5%), GROW 15.9%다. Part 1에서 A만 고르든 C만 고르든 Top1은 100% EXP가 된다.
- 원인: EXP는 4문항·3맥락에만 나오고, E03·E06에서 한 문항 안에 두 번 등장한다. 그래서 분모(상한 8점, 맥락 3개)가 작아 `selection`과 `diversity`가 쉽게 100에 닿는다([structure.md](structure.md)).
- 페르소나 결과에서도 EXP가 Top1의 25%(의도 13%)였고, AUT는 2%(의도 13%)로 눌렸다.
- 설계서 4장도 "EXP 12점·GROW 14점"이라 적었지만 문항당 2점 제한 때문에 실제 상한은 8·12점이다(spec-auditor가 찾은 내부 모순).
- 제안: 이 규칙은 설계서에 식이 없는 앱 임시 규칙이므로 재설계 대상이다. 예를 들어 등장 횟수가 다른 가치는 원점수 비율 대신 기대값 대비로 보정하거나, E03·E06·E14의 중복 가치를 해소한다. `SCORING_VERSION`을 올려야 하는 변경이다.

### 2-3. [설계 공백] Part 1 선택지 위치 편중
- A 위치에 TRUST가 0번, C 위치에 DEPTH·FLOW가 각 4번 배치되어 있다. 첫 보기를 고르는 경향(초두 효과)이 있는 응답자에게는 Core가 체계적으로 기운다(몬테카를로: A 고정 → 100% ORDER, C 고정 → DEPTH 59%·FLOW 41%).
- 제안: 문항 원문은 유지하고 화면에서 선택지 표시 순서만 문항별로 고정 섞기를 하면 된다. 응답 키는 그대로 두면 채점에 영향이 없다.

### 2-4. [설계 공백] 판정 유보·약한 동기 플래그가 거의 작동하지 않음
- 의도한 판정 유보형 4건은 0건 탐지(재현율 0%)였다. 의도한 약한 동기형 4건도 0건 탐지였다.
- 판정 유보는 TypeScore→M→1순위 횟수가 **모두** 같아야 성립한다. 18문항 선택형에서는 거의 생기지 않는다(무작위 3.6%). "두 힘이 비슷한 사람"을 판정 유보로 잡으려면 근접 기준(예: TypeScore 차 ≤ 1점)이 필요하다. 설계서에는 근거가 없으므로 결정 사항이다.

### 2-5. [설계 공백] 반증(Counterevidence) 정밀도 낮음
- 반증 플래그는 재현율 44%, 정밀도 33%다. 의도하지 않은 16건에서도 반증이 붙었다.
- 사회적 바람직성 스타일 응답(몬테카를로)에는 **100%** 반증이 붙는다. "잘 보이고 싶은 사람"은 문제 신호를 낮게 답하므로 전형 신호가 늘 낮게 나온다. 그 결과 Core 설명이 일괄 약화된다.
- 제안: 반증 판정 전에 응답 스타일(전 문항 저점·고점 경향)을 확인하거나, 반증 기준(45)을 Core별로 재추정한다.

### 2-6. Step 1 참고: 설계서 내부 모순 11건, 미정의 12건
[reference-notes.md](../reference-notes.md)에 근거와 함께 정리했다. 주요 항목은 다음과 같다.
- 응답 일관성 기준의 두 서술이 서로 다른 조건이다.
- CoreConfidence Penalty가 정의되어 있지 않다.
- 트리거 기준 65는 25점 간격 점수에서 사실상 75와 같다.
- 10.6 예시 값(SC3 68, SR 74)은 실제로 나올 수 없는 값이다.

## 3. 정확도 — 리포트가 truth와 얼마나 맞는가

| 지표 | 일반 응답(54건) | 비고 |
|---|---:|---|
| Core Top1 / Top2 | 54% / 69% | 의도 Core별 17%(CARE)~83%(TRUST) |
| ANX 구간 / AVO 구간 | 85% / 65% | 두 축 독립 해석 |
| Schema Top3 겹침 | 68% | |
| Value Top3 겹침 / Top1 | 70% / 67% | |
| STATE 밴드 | 83% | |
| 스트레스 반응성 / 취약 트리거 | 54% / 44%(Jaccard) | 반응성 문항 SR 3개의 내적 일관성이 낮음(r 0.55) |

**Core가 어디로 흡수되나** (혼동행렬, [metrics.md](metrics.md) §3)
- **FLOW 흡수**: 결과 Primary의 23%가 FLOW다(의도 10%). CARE→FLOW 4, ORDER·SPARK→FLOW 각 2이고, 엣지 p28(평평함)·p30(성의 없음)도 FLOW로 판정됐다. FLOW 선택지는 "갈등을 만들지 않는 무난한 답"이라, 특징이 약하거나 대충 고르는 응답이 이쪽으로 모인다. 무작위 응답에는 이 쏠림이 없으므로(11.1%) 엔진 구조가 아니라 **선택지 문구의 바람직성** 문제로 보인다.
- **STAND 과소**: 결과 3%(의도 10%). STAND 선택지("그 자리에서 바로 반대 의견을 낸다" 등)는 공격적으로 읽혀서 자기 보고에서 덜 선택된다.
- **반증형은 Core부터 놓친다**: Case가 반증형이면 Core Top1이 31%이고, Supporting 수준 low는 33%, high는 83%다. 전형 신호가 약한 사람은 Part 1 선택에서도 이웃 Core로 흩어진다. 반증 장치는 설명을 약하게 할 뿐 Core 판정 자체를 보정하지 않으므로, 이 집단의 결과는 "잘못된 Core + 약한 설명"이 되기 쉽다.

**행동 변수와 정확도**
- 자기 성향을 확신하는 2명(p03: 실제 ORDER·믿음 INSIGHT, p19: 실제 SPARK·믿음 DRIVE)은 두 회차 모두 **실제 성향**으로 판정됐다. 선택형 장면 문항이 자기 라벨에 덜 휘둘린다는 긍정 신호다.
- 힘든 시기 4명은 Core Top1이 25%다. 최근 상태가 동기 선택까지 물들인다. STATE는 맞췄다.
- 집중력이 낮은 집단의 정확도가 오히려 높게 나왔다(71%). 이는 LLM 응답자가 "대충" 답해도 일관성을 유지하기 때문으로 보이며 실제 사람과 다를 가능성이 크다(한계).

|---|---|---|---|---|
| Primary Core | FLOW 23% 최다, STAND 3% | 각 10% | 균등(10.3~11.7%) | 문구 바람직성 쏠림 |

## 5. 납득도 — 읽고 "맞다"고 느끼나

- "나 같다" 3.5/5, 신뢰 2.9/5, 이해받았다는 느낌 73%, 공유 의향 yes 10%·maybe 77%.
- **정확도 × 납득 사분면**(합성 정확도 ≥0.6, 납득 ≥4):

| | 납득 | 불납득 |
|---|---:|---:|
| 정확 | 15명 (50%) | 7명 (23%) — 맹점·전달 문제 |
| 부정확 | 2명 (7%) — 바넘 위험 | 6명 (20%) |

- 섹션 단위로 "느낌"과 "실제 맞음"을 교차하면 **실제로 맞는데 '애매'하다고 느낀 경우가 54회**로 가장 많다. 엔진이 맞혀도 전달 과정에서 잃는 몫이 크다.
- 맹점(자기 인식 차이 large) 페르소나는 거부한 문장 중 맹점 문장 비율이 높다(평균 2.4개). 맹점을 짚는 문장은 정확해도 거부되기 쉬우므로, 단정형보다 질문형으로 쓰는 것이 낫다.
- 섹션별로는 STATE·STRESS·PATTERN·RELATIONSHIP이 잘 받아들여졌다(70~96%). 반면 **STATE 건강/스트레스 해설(4%), CORE 사용 방식(14%), GROWTH(12%), 메시지(27~33%)**는 거의 받아들여지지 않았다. 유형별 고정 해설·메시지 카드가 개인 장면과 연결되지 않는다는 반응이다.
- 이해 안 된 용어(30명 중): Influence 28, 보조 Core 25, 반응성 23, Protection/Expansion Mode 18, 성장 준비도 15, 동기 진술 15, 겹침 강도 14, Layer 8. **끝까지 읽은 사람은 50%**, 읽기 부담은 4.0/5다.

**정서적 안전성** — 최근 힘든 시기 4명(이별·번아웃 휴직·실직·사별)
- 4명 모두 납득 3~4점으로 내용은 맞다고 느꼈지만, 각 2~3개 문장을 "읽기 아프다"고 지목했다. 예:
  - 이별 3주 차에게 "미리 하는 이별 연습"이라는 비용 라벨
  - 사별 5주 차에게 "돌봄이 확인받고 싶어서냐"는 메시지 질문
  - 번아웃 휴직자에게 "괜찮은 척하지만"
- 그 밖에도 "통제하려 들 수 있어요", "분노로 바뀌면", "가혹함" 같은 단어가 낙인처럼 읽혔다는 지적이 많았다.
- 제안: STATE가 보호 밴드이거나 최근 힘든 신호가 있을 때는 비용·그림자 문장의 강도를 낮추고 회복 쪽 문장을 앞에 둔다. "분노·통제·가혹함·척" 같은 단어는 행동 서술로 바꾼다.

## 7. 리포트 변별력과 바넘 문장

- 골라내기 97%(29/30)로 리포트는 사람마다 확실히 구별된다. 하지만 판정 사유를 보면 근거는 주로 **점수·Core 조합·트리거·관계 축 수치**였다. 한 평가자는 "같은 TRUST 템플릿을 공유해 핵심 문단으로는 구별되지 않는다"고 적었다(t05). 다른 사람끼리 문장 Jaccard는 0.34이고, **그 사람에게만 나온 문장은 리포트 문장의 4%**뿐이다. 개인화된 문장 섹션 안에서도 103개 문장이 30명 모두에게 똑같이 나왔다.
- 평가자가 "누구에게나 맞는다"고 지목한 문장(30명 중 지목 수):
  - (26) 패턴은 결함이 아니라 오래 사용해온 내면의 규칙이에요.
  - (24) 이 상태는 성격이 아니라 계절 같은 거예요. 다음 달에 다시 재면 달라질 수 있어요.
  - (15) 이 지점은 약점이 아니라, 무엇이 중요한 사람인지를 거꾸로 보여주는 지도이기도 해요.
  - (14) 이 리포트에서 가장 오래 마음이 멈춘 문장은 무엇이었나요?
  - (10) 이 힘들은 누구에게나 조금씩 있어요.
- 문장 빈도로 본 바넘 후보(30명 중 비율): "다만 동기 진술에서는 주된 힘만큼 강하지 않아…"(90%), "서로 다른 Layer가 같은 쪽을 밀면…"(80%), "익숙한 반응이 자동으로 나오기 전에 한 박자 멈추고…"(73%).
  - 이 중 상당수는 해석 원칙을 알려 주는 안내문이라 반복 자체가 문제는 아니다.
  - 다만 **"다만 동기 진술에서는…"이 90%에 나오는 것**은 Influence 설명이 거의 모든 사람에게 같은 조건으로 붙는다는 뜻이므로 조건을 점검해야 한다.

## 8. MBTI·사전 지식·자기 인식

- MBTI는 정답지 속성이고 앱은 측정하지 않는다.
  - T 성향 16명은 ANX 평균 33·Core 적중 69%, F 성향 14명은 ANX 68·Core 적중 43%였다.
  - F 성향의 결과 Core는 FLOW·CARE·DEPTH로 모였다. 감정형 페르소나일수록 FLOW 흡수(§3)에 더 노출된다.
- 예전 MBTI가 지금과 다른 3명(p03·p19·p27) 중 p03·p19는 의도한 Core로 판정됐다. p27(의도 FLOW)은 DEPTH로 판정됐는데, 이것이 MBTI 라벨(INFP) 때문인지는 이 표본으로 구분할 수 없다.
- 자기 인식 차이가 큰 사람의 Core 정확도는 오히려 높았다(large 70%, none 38%). 장면 문항이 자기 인식보다 행동을 더 잘 끌어낸다는 신호다. 다만 이들의 납득도는 낮았다(3.40). 정확한 결과가 꼭 받아들여지지는 않는다는 §5의 결론과 같은 방향이다.

## 9. 개선 제안 (우선순위)

| 순위 | 대상 | 제안 | 성격 |
|---|---|---|---|
| 1 | `report.tsx` PATTERN | 2·3위 규칙을 점수 구간에 따라 문장 강도 조절, 동점 표시 | 리포트 결함 |
| 2 | Value 정규화(임시 규칙 1) | EXP·GROW 상한 차이 보정, 중복 가치 문항 해소 | 엔진 설계, `SCORING_VERSION` 상향 |
| 3 | 리포트 용어 | Influence·보조 Core·반응성·Expansion/Protection Mode·성장 준비도·동기 진술·겹침 강도를 한국어 일상어로 바꾸고 첫 등장에 한 줄 설명 | 전달 |
| 4 | 리포트 길이 | 절반이 끝까지 안 읽음 → 요약 1페이지와 펼쳐 보기 구조, 고정 해설(STATE 건강/스트레스, CORE 사용 방식)은 접기 | 전달 |
| 5 | 정서적 안전성 | 보호 밴드·힘든 신호에서 비용·그림자 문장 강도 낮추기, 낙인 단어 교체 | 전달·안전 |
| 6 | 문항 M5, P2 | 표현 수정 후보(설계서 원문 변경이므로 근거와 버전 기록 필요) | 문항 |
| 7 | Part 1 표시 순서 | 선택지 표시 순서 고정 섞기 | UI |
| 8 | 판정 유보·반증 기준 | 근접 동점 기준 도입 검토, 반증 전 응답 스타일 확인 | 엔진 설계 |

모든 임계값과 가중치는 파일럿 전 가설값이다. 위 제안은 이 시뮬레이션의 이상 신호에서 나온 **후보**이며, 파일럿(권장 n ≥ 150)과 인지면담으로 확인한 뒤 확정해야 한다.
