# 검증용 가정

이 파일의 내용은 **검증 절차를 위한 가정**이다. 설계서 원본 규칙도 앱 채점 규칙도 아니다.
앱의 임시 채점 규칙은 [docs/scoring-decisions.md](../docs/scoring-decisions.md)에 따로 있다.

| # | 가정 | 이유 |
|---|---|---|
| V1 | 응답자에게는 문항 ID 대신 화면 순서 번호(Q01~Q76)만 보여준다. 변환은 `scripts/common.ts`의 `NEUTRAL_TO_ITEM`이 맡는다. | A1·S3·ST2 같은 ID 접두어가 측정 영역을 드러낸다. |
| V2 | 정답지의 0–100 점수 구간은 low < 40 · mid 40–59 · high ≥ 60으로 본다. | 앱의 4단계 표시 구간(`report.ts`의 `band`: <40 · 40–59 · 60–74 · ≥75)을 3단계로 묶어 의도 비교에 쓴다. 앱 판정에는 쓰지 않는다. |
| V3 | 설계서 대조(Step 1)는 설계서에 식이 있는 항목만 대상으로 한다. `scoring-decisions.md`의 "임시 규칙" 1–10은 앱 가정으로 분리 표시한다. | 원본에 없는 규칙을 원본과 비교할 수 없다. |
| V4 | 무작위 응답 생성은 시드 고정 PRNG를 쓴다. Part 1은 서로 다른 (1순위, 2순위) 6쌍 균등, 5점은 1–5 균등, Part 6은 6가지 순열 균등. | 재현 가능한 기준선. |
| V5 | 30명 결과는 이상 신호를 찾는 스모크 테스트로만 해석하고 통계적 판정에 쓰지 않는다. | 표본이 작다. 분포 판단은 몬테카를로 기준선과 함께 읽는다. |
| V7 | Case 5종(Reinforced·Counterevidence·Conflict·Compensation·Basic)은 `designer-brief.md` 2장의 검증용 정의를 쓴다. 앱은 Reinforced(강화)·Counterevidence(반증)만 판정하므로 나머지 셋은 Case별 정확도로만 본다. | V1.0 앱에는 Case 판정이 없다. |
| V8 | 납득도 사분면의 정확도 합성값 = run1의 (Core Top1, ANX 구간, AVO 구간, Schema Top3 겹침, Value Top3 겹침, STATE 일치) 평균, 기준 0.6. 납득 기준은 `overall_fit` ≥ 4. | 페르소나 단위로 정확도와 납득을 교차하기 위한 단순 합성. |
| V9 | 응답 경험은 run1에서만 기록한다. run2는 응답만 받는다. | 같은 사람이 같은 검사를 두 번 체감하는 것은 현실과 다르다. |
| V10 | 배치표는 `truth/_matrix.md`에 둔다(요청 원문은 `personas/_matrix.md`). | `personas/`는 응답자가 접근하는 폴더라 정답 정보를 두지 않는다. |
| V11 | 페르소나·응답자·독자·평가자는 모두 같은 계열의 언어 모델이다. 역할과 읽을 수 있는 파일을 분리했지만, 실제 사람의 응답·체감·납득을 대신하지 않는다. | LLM 시뮬레이션의 한계. 파일럿의 인지면담으로 확인해야 한다. |
| V6 | 설계서 텍스트는 docx에서 추출한 `spec/design-v1.txt`를 쓴다. 표는 `|`로 구분되며 수식 객체·그림은 빠질 수 있다. | 원본 docx는 수정하지 않는다. 의심스러운 부분은 원본을 직접 확인한다. |
