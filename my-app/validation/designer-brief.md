# 페르소나 설계 브리프 v2 (persona-designer 전용)

이 문서는 persona-designer만 읽는다. 응답자(respondent)·독자(persona-reader)·평가자(blind-judge)에게는 전달하지 않는다.
여기의 코드(T1, ANX, US …)는 `truth/` 파일에만 쓰고 bio에는 쓰지 않는다.
1차 설계(round1)는 `archive/round1/`에 보관되어 있으며 참고하지 않는다.

이번 라운드는 세 가지를 함께 본다.
- **정확도**: 리포트가 truth와 얼마나 맞는가 (엔진 품질)
- **납득도**: 페르소나가 리포트를 읽고 "맞다"고 느끼는가 (전달 품질) — 자기 인식(self-image)이 truth와 다를 수 있다
- **응답 경험**: 문항이 어렵거나 지루하지 않은가 — 사람마다 동기·집중력·컨디션·숙련도가 다르다

## 1. 측정하는 6 Layer (개념만)

### CORE — 무엇이 나를 움직이는가
| 코드 | 이름 | 핵심 동기 | Supporting Variable(함께 높으면 강화) | 전형 신호(낮으면 반증 후보) |
|---|---|---|---|---|
| T1 | ORDER | 옳은 기준을 지키고 바로잡고 싶음 | US 스스로에게 높은 기준 | US |
| T2 | CARE | 누군가에게 필요한 사람이 되고 싶음 | SS 나보다 상대 먼저 | SS |
| T3 | DRIVE | 해내야 가치 있다고 느낌 | AS 인정에 기대기 | AS |
| T4 | DEPTH | 나다운 의미와 감정의 깊이 | DEF 부족함이 드러날 걱정 | DEF · ED |
| T5 | INSIGHT | 충분히 이해한 뒤 움직이고 혼자 생각할 공간이 필요 | AVO 친밀감 거리두기 | AVO |
| T6 | TRUST | 믿을 수 있는 기반을 찾고 미리 대비 | ANX + ABN 관계 흔들림 민감 | ANX · ABN · MIS |
| T7 | SPARK | 새로운 가능성과 즐거움, 답답함을 못 견딤 | ST4 선택지 없을 때 흔들림 | ST4 |
| T8 | STAND | 휘둘리지 않고 앞에 나서서 지킴 | MIS 의도부터 살핌 | MIS |
| T9 | FLOW | 평화와 조화, 갈등과 자기주장을 피함 | ST5 말하지 못할 때 흔들림 | SS · ST5 |

생활 만족 채널(하나): SP 생활의 안정 · SO 소속과 자리 · SX 한 사람과의 깊은 연결

### STATE — 지난 한 달의 상태 (성격 아님)
자기연민, 마음의 유연함, 자율·유능감·관계 욕구 충족. 밴드: expansion(여유) · balanced(평소) · protection(보호).

### RELATIONSHIP — 두 축을 독립적으로
- ANX 관계 변화 민감도 · AVO 친밀감 거리두기
- 안정(둘 다 낮음) / 불안(ANX만 높음) / 회피(AVO만 높음) / 혼합(둘 다 높음)

### PATTERN — 반복되는 내면 규칙 8개
ABN 관계가 끝날 것 같은 감각 · ED 이해받지 못할 거라는 기대 · MIS 의도부터 살핌 · DEF 부족함이 드러날 걱정 ·
DEP 혼자 판단하기 어려움 · SS 나보다 상대 먼저 · AS 남의 인정이 선택 기준 · US 스스로에게 높은 기준

### STRESS — 흔들리는 상황과 대처
트리거: ST1 기준에 못 미칠 때 · ST2 필요 없다고 느낄 때 · ST3 앞이 안 보일 때 · ST4 선택지가 없을 때 · ST5 말하지 못할 때 · ST6 사람들 사이 갈등
반응성(SR): 회복 속도와 감정 요동 · 대처: SC1 과업 몰입 · SC2 철수 · SC3 확인·위로 찾기 · SC4 밀어붙이기 · SC5 주의 전환 · SC6 자기비난

### DIRECTION — 가치 8개
ACH 성취 · AUT 자율 · REL 관계 · SEC 안정 · GROW 성장 · AUTH 진정성 · CONTR 기여 · EXP 경험·즐거움

## 2. Case 5종 (검증용 정의)

앱 엔진은 이 중 Reinforced(강화)와 Counterevidence(반증)만 직접 판정한다. 나머지 셋은 점수 조합으로 드러나는지 본다. 이 정의는 검증용이며 설계서 원문 규칙이 아니다.

| Case | 정의 | 예 |
|---|---|---|
| Reinforced | Core와 그 Supporting Variable이 함께 강함 | ORDER + 스스로에게 높은 기준 |
| Counterevidence | Core는 뚜렷한데 그 Core의 전형 신호가 낮음 | 자기희생·인정 불안이 낮은 CARE, 인정 민감성이 낮은 DRIVE |
| Conflict | 서로 반대로 당기는 두 성향이 함께 높음 | 자율 가치↑ + 인정에 기대기↑ / 관계 가치↑ + 거리두기↑ |
| Compensation | 한 강점이 취약성을 덮는 방식으로 작동 | 부족함 걱정↑을 성과·과업 몰입으로 덮음 / 이해받지 못할 기대↑를 철저한 자기해결로 덮음 |
| Basic | Core가 뚜렷하고 특별한 상호작용 없음, Supporting Variable 중간 | — |

## 3. 30명 배치 규칙

### Core
- p01–p27: T1–T9 각 3명. p28 평평함(어떤 Core도 뚜렷하지 않음) · p29 모든 반응이 극단적 · p30 성의 없음(회사 권유로 억지로 응시).
- 같은 Core 3명은 서로 다르게:
  - 관계: 안정 / 불안 / 회피 / 혼합 중 서로 다른 셋
  - Supporting Variable: 높음 1 · 낮음 1(반증 후보) · 중간 1
  - 예상 Case: 3명이 모두 같지 않게
- STATE 밴드는 30명에서 대략 1:1:1. 가치 Top1은 8개 모두 2명 이상. 스키마별 Top3 등장은 6~12명.

### Case 최소 개수 (p01–p27 주 Case 기준)
Counterevidence 5 · Conflict 5 · Compensation 4 · Reinforced 4 · Basic 4 (나머지 5명은 자유, 보조 Case 허용)

### 행동 변수 (30명 전체에 겹쳐 배치, Core와 독립적으로 섞기)
| 변수 | 분포 |
|---|---|
| 연령 | 20대 8 · 30대 8 · 40대 7 · 50대 이상 7 |
| 검사 동기 | 스스로 찾아옴 12 · 지인·회사 권유 10 · 그냥 호기심 8 |
| 집중력 | 높음 10 · 보통 13 · 낮음 7 |
| 사회적 바람직성(잘 보이고 싶음) | 높음 5 |
| 성격검사 사전 지식 있음 | 7 (그중 2명은 자기 성향을 이미 확신 — `believed_core`에 기록, truth와 다를 수 있음) |
| 최근 힘든 시기(이별·실직·번아웃 등) | 4 — 정서적 안전성 검증용 |
| 디지털·심리용어 익숙도 낮음 | 5 (주로 50대 이상) |
| 읽기 속도 · 검사 당일 컨디션 · 검사 환경(폰/PC, 장소) | 사람마다 다양하게 |

### MBTI
- 30명 모두 `mbti.type`(장면·성향에 맞는 MBTI)과 `fit_note`를 정한다. Core와 1:1로 고정 매핑하지 않는다. E/I·S/N·T/F·J/P 각 축에서 한쪽이 20명을 넘지 않게.
- 사전 지식이 있는 7명만 `self_reported`(본인이 안다고 말하는 MBTI)를 둔다. 2명 이상은 예전 결과가 지금과 다르다(type ≠ self_reported).
- bio에는 이 7명만 "검사를 대하는 태도"에 self_reported를 쓸 수 있다(네 글자 코드 허용은 이 경우 한정).

### 자기 인식(self-image)
- 모든 사람에게 1인칭 자기 인식을 쓴다. 최소 10명은 장면과 일부러 어긋나는 맹점을 둔다(`self_image_gap.level`: small 또는 large, large는 4명 이상).
- 예: 장면에서는 남의 반응을 계속 확인하는데 "나는 남 눈치 안 보는 편이에요"라고 말함.

## 4. 파일과 템플릿

- 배치표: `truth/_matrix.md` — 30명 표 + **하단에 분포 집계표**(위 모든 분포를 실제로 센 값). `personas/`에는 두지 않는다(응답자 접근 폴더).
- 응답자용: `personas/pXX_bio.md` — 템플릿 `personas/_template_bio.md`
- 정답지: `truth/pXX_truth.json` — 템플릿 `truth/_template_truth.json`

## 5. bio 작성 규칙

- 성향을 형용사로 설명하지 말고 장면으로 보여준다.
  - 나쁜 예: "그는 인정 욕구가 강하다."
  - 좋은 예: "팀장에게 보고서를 낸 날은 답장이 올 때까지 메신저를 몇 번씩 열어본다."
- 장면 7개 필수: 일 · 가까운 관계 · 갈등 · 휴식 · 실패 · 낯선 상황 · 칭찬이나 비판을 받았을 때
- 지난 한 달의 상태, 하루를 잘 보냈다고 느끼는 순간, 바라는 삶을 넣는다.
- "자기 인식"은 본인의 1인칭 문장. 장면과 어긋날 수 있다(맹점).
- "말투 샘플" 2–3문장으로 목소리를 고정한다.
- "검사를 대하는 태도"에 검사 동기, 집중력·읽기 속도, 오늘 컨디션, 검사 환경, 이런 검사에 대한 생각을 쓴다. 사전 지식은 "MBTI나 성격검사를 즐겨 한다", "나는 무조건 목표형 인간이라고 굳게 믿는다"처럼 쓴다.
- **금지어**: 유형, 에니어그램, 스키마, 애착, Core, T1~T9, ORDER·CARE·DRIVE·DEPTH·INSIGHT·TRUST·SPARK·STAND·FLOW, 회피형·불안형, 점수, 진단명, 가치 이름을 라벨처럼 나열하는 표현. ("MBTI"라는 단어와 네 글자 코드는 사전 지식이 있는 7명의 "검사를 대하는 태도"에서만 허용.)
- 800~1,400자. 사람마다 문체·구성 순서·말투를 다르게.

## 6. 완료 전 점검 (`truth/_matrix.md` 하단에 결과 기록)
1. 같은 Core 3명의 bio를 나란히 놓았을 때 서로 다른 사람으로 읽히는가
2. bio 금지어 Grep 결과 0건인가
3. truth를 가리고 bio만 읽어도 주요 성향을 추측할 수 있는가 (각 Core에서 1명씩 스스로 블라인드 추측 → 결과 기록)
4. 30명 전체가 3장의 분포를 만족하는가 → 분포 집계표
